# Summary

Fuzzy-logic modifiers that serve as linguistic hedges — intensifiers and dilators such as *very* or *somewhat* — transforming fuzzy concepts by remapping their membership degrees across the normalized [0, 1] interval within a fuzzy description-logic knowledge base.

## Description

An abstract base class, Modifier, anchors the hierarchy and establishes the shared contract that every hedge must honour: deriving a printable name, producing a functionally independent clone, applying the transformation to a fuzzy concept, and computing the modified membership degree for a real-valued input, with the only guaranteed invariant being that results stay within the normalized [0, 1] interval. The base class deliberately contains no mathematics of its own, because intensification, dilation, and other hedges differ in how they reshape membership functions, so concrete subclasses supply the actual shapes: one performs a piecewise linear transformation governed by a single coefficient that positions a hinge point inside the unit interval, preserving both endpoints while warping the interior to express graded hedges such as *very* or *fairly*, while the other implements the classic triangular membership function that rises linearly from zero at a left boundary to full membership at a peak before descending back to zero. A central design decision is that modifiers never mutate the concepts they touch; instead, each application wraps the original concept in a corresponding modified-concept object, deferring the actual degree computation to evaluation time so that modified and unmodified forms can coexist in the knowledge base and be reasoned about independently. Both concrete implementations overload the negation, conjunction, and disjunction operators to delegate to operator concepts, letting hedges be composed inside compound fuzzy expressions using natural Python syntax. Supporting conventions round out the design: hashing is based on each modifier's name and parameters so structurally equivalent instances behave correctly as dictionary keys and set members, cloning allows a single modifier to be reused across many concepts without risking shared mutable state, and names are derived lazily and cached so freshly created modifiers identify themselves without precomputing labels they may never need.
