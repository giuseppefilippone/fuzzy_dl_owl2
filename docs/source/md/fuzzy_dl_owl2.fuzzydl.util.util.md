# Summary

A centralized utility namespace for a fuzzy description-logic reasoner that pairs lazily self-configuring file logging with a small set of numeric and list-manipulation helpers.

## Description

Logging is organised around a module-level reasoner logger that wires itself up on demand: the first time any message is emitted, a timestamped file handler is attached and pointed at a dated directory tree under ./logs/reasoner/<year>/<month>/<day>, so the rest of the codebase never needs explicit initialisation. The static helpers on the central **Util** class act as the reasoner's single gateway to that logger — debug output is additionally gated behind the ConfigReader.DEBUG_PRINT flag, which also determines whether the effective level is DEBUG or INFO, and propagation to the root logger is disabled to avoid duplicate records. Error handling is deliberately fused with control flow: reporting an error both records the message and immediately raises a FuzzyOntologyException carrying it, so a single call both documents and aborts a failure. Alongside logging, the class offers mathematical conveniences tailored to the reasoner's needs, most notably a rounding routine built on Decimal with ROUND_HALF_UP semantics and a configurable number of digits, chosen to sidestep the binary floating-point artefacts and banker's rounding of Python's built-in round; the remaining helpers cover integral-value checks on floats, power-of-two sizing via the ceiling of a base-2 logarithm, and in-place sorting keyed on string representations so that heterogeneous collections can still be ordered deterministically. Keeping everything as stateless static methods on one class gives callers a single import point for these cross-cutting concerns without requiring instances or shared mutable state.
