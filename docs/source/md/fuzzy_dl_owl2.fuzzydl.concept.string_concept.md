# Summary

Defines an atomic fuzzy-description-logic concept that wraps a single string literal, presenting it as a quoted, indivisible leaf node that cannot be logically complemented.

## Description

Within a fuzzy description logic framework, textual values such as names and labels need to participate in the same concept hierarchy as more complex logical expressions, and `StringConcept` provides exactly that wrapper: it subclasses the generic `Concept` type, tags itself as atomic, and stores the raw textual value internally. Its canonical name is always rendered as a double-quoted literal, which keeps string values clearly distinguishable from ordinary atomic concept identifiers when concepts are printed, serialised, or compared. Because it is deliberately a terminal node in the concept tree, queries for associated roles or for constituent atomic concepts return empty sets, and structural replacement operations simply hand back the instance unchanged, preserving its identity during expression rewriting. One semantic restriction is enforced explicitly: applying the unary negation operator, which in this logic denotes complementation, raises an exception, since a bare string literal has no meaningful complement. Hashing is derived from the stored name together with the concept type rather than object identity, so two instances wrapping the same text behave as equal and interchangeable values, and a cloning operation yields an independent copy carrying the same literal.
