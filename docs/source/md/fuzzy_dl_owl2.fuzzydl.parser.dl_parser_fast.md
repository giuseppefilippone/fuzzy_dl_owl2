# Summary

A faster drop-in replacement for the legacy fuzzy-DL parser that pairs a hand-rolled tokenizer with a deterministic recursive-descent parser to load fuzzy description-logic knowledge bases and answer queries, reusing the original parser's semantic actions so the resulting knowledge base and queries are populated exactly the same way.

## Description

The central `_Parser` class performs a single left-to-right pass over a pre-lexed token list, committing to a grammar branch with only one token of lookahead and never backtracking — a safe strategy because the fuzzy-DL grammar is LL(1) at the top level and the tokenizer has already disambiguated numbers, identifiers, and punctuation. Dispatch decisions are driven by frozenset membership tests over keyword literals that are pulled directly from the `FuzzyDLKeyword` enum rather than duplicated as string constants, so any upstream keyword rename is picked up automatically on the next process start. For every grammar production the parser forwards a flat token list to the corresponding `_parse_*` semantic-action callback on the imported `DLParser` class, which means all knowledge-base construction, feature-type dispatch, and query registration logic remains shared between the fast and legacy implementations as a single source of truth.

The public facade, `DLParserFast`, mirrors the legacy API method-for-method — parsing a string or a file, loading configuration, returning the populated knowledge base together with its query list, and running the complete parse/solve/answer pipeline — so callers can swap implementations without touching call sites. Memory behaviour is tuned for large ontologies: small inputs are tokenized and parsed in one pass, while bigger sources are streamed form-by-form in bounded chunks so peak token memory stays proportional to a single chunk, and when the optional compiled re2c/flex backend is available the input file is memory-mapped and tokenized in C with per-chunk timings logged. The cyclic garbage collector is deliberately disabled during bulk parsing and the full run, because the constructed concepts, axioms, and MILP terms form a large acyclic object graph with nothing to reclaim until the end, and repeated O(N) collector sweeps would be pure overhead; the prior collector state is always restored afterwards. The implementation is also written to be Cython-compilable for an additional native-code speedup, and even in plain Python it parses roughly 5–10x faster than the legacy parser because backtracking, packrat caching, and bounded-recursion machinery are gone.

Robustness details are handled inline: parse errors raise a dedicated ontology exception carrying the byte offset and offending token, unexpected failures are wrapped while preserving the original exception type in the message, missing files are reported and re-raised, and an inconsistent ontology is surfaced as a defined answer rather than a crash. A few tokenizer quirks receive special treatment, such as splitting a threshold operator fused to its operand (for example `>=0.4`) back into operator and value, and disambiguating `range` forms between feature declarations and role axioms by peeking at the third token inside the parentheses.
