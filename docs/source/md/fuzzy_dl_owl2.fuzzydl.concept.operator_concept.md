# Summary

A fuzzy description-logic concept representing conjunctions, disjunctions, and negations, together with the simplification machinery needed to normalise compound expressions under classical, Łukasiewicz, and Gödel (Zadeh) semantics.

## Description

`OperatorConcept` is the central building block for compound logical expressions in a fuzzy DL knowledge base: it wraps a list of operand concepts together with an operator type drawn from three semantic families (classical, Łukasiewicz, and Gödel), and it maintains a cached, human-readable name derived from that structure. Users rarely instantiate it directly; instead, static factories such as `and_`, `or_`, and `not_` consult the globally configured knowledge-base semantics to select the appropriate operator variant, flatten nested operators of the same kind into a single n-ary node, and immediately push the result into the corresponding conjunctive normal form, so expressions are canonical from the moment they are created. Explicit Gödel and Łukasiewicz variants of the factories exist for callers that need to pin a specific semantics, and module-level aliases expose these factories as plain functions for convenient use elsewhere.

Which algebraic simplifications are legal depends on the fuzzy logic in play, and OperatorConcept encodes this knowledge in class-level operator tables: complement laws are admitted for classical and Łukasiewicz connectives, distributivity and absorption for classical and Gödel ones, while Łukasiewicz connectives deliberately forgo distribution because it is not sound in that logic. A normal-form driver then iterates a fixed pipeline — De Morgan transformations that push negations inward, double-negation elimination, distribution of one operator over its dual, idempotency and complement-law reductions, and truth-value simplifications involving ⊤ and ⊥ — until a fixed point is reached, yielding CNF or DNF depending on which operator was chosen for distribution. Quantifier reasoning is woven into the same pipeline: universal restrictions that share a role are merged under conjunctions and existential restrictions under disjunctions, so expressions like ∀r.C ∧ ∀r.D collapse into a single quantifier with a conjoined restriction.

Beyond construction and normalisation, a large family of static type-guard predicates answers questions such as whether a concept is a negated fuzzy number, weighted sum, OWA aggregation, or Choquet/Sugeno integral, which other components rely on when deciding how to process negated expressions. Operator overloading of `&`, `|`, and unary `-` lets users write logical expressions with natural Python syntax, and equality as well as hashing are derived from the structural string representation so that logically identical expressions deduplicate inside sets. One deliberate divergence from the original Java implementation is worth noting: substitution rebuilds a node using the receiver's own operator type rather than dispatching on the replacement's type, which preserves logical polarity that the Java version mishandled.
