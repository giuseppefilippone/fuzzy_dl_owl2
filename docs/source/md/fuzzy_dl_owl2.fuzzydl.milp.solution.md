# Summary

A value object that captures the outcome of a query over a fuzzy knowledge base, pairing a numerical degree of satisfaction with the knowledge base's consistency status and any variable bindings produced during solving.

## Description

The `Solution` class serves as the canonical result type handed back by the reasoning machinery whenever a query is posed against a fuzzy knowledge base. Its central design decision is a dual-mode constructor: passing a number records the degree of satisfaction obtained for the query and implicitly assumes the knowledge base is consistent, whereas passing a boolean explicitly encodes the consistency verdict, in which case the numeric value is meaningless and defaults to zero. Type-based dispatch inside the constructor — backed by `typing.overload` stubs for the benefit of static type checkers — routes the single argument to the appropriate private initializer and raises a `TypeError` for anything that is neither a boolean nor a number, keeping call sites honest. Beyond the headline value, the object accumulates a dictionary of *showed variables*, the bindings the solver determined for variables the user asked to expose, which can be grown incrementally as results are extracted and read back afterwards. Hashing is defined over the triple of solution value, consistency flag, and the frozenset of variable bindings so that instances can participate in sets and dictionaries, though the hash shifts if bindings are added after the object has been inserted into a hash-based container. The human-readable rendering deliberately collapses both modes into a single message — a consistent base prints its numeric answer while an inconsistent one simply reports "Inconsistent KB" — and the class-level `CONSISTENT_KB` and `INCONSISTENT_KB` constants give callers readable names when constructing the boolean form.
