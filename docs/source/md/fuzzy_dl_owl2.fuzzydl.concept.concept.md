# Summary

Defines the core concept representation for a fuzzy description logic reasoner, pairing an abstract base class for logical expressions with the central **Concept** class to support normal-form conversion, expression simplification, and operator-overloaded logical composition.

## Description

A fuzzy description logic reasoner represents knowledge as concept expressions, and two central classes form the backbone of that representation: **Thing**, an abstract base for every kind of logical entity, and **Concept**, the concrete type that tags each expression with a structural classification and a printable name. Thing is built around a template-method design in which transformation steps such as truth-value reduction, idempotency and double-negation elimination, De Morgan application, quantifier reduction, and distribution default to harmless pass-throughs that simply return the receiver; leaf-like behaviour is therefore the norm, and compound subclasses override only the steps relevant to their structure, letting generic traversal code run without type checks. On top of these primitives sits a family of normal-form entry points that convert an expression into classic CNF or DNF as well as their Gödel and Łukasiewicz counterparts, each delegating to a single generic *normal_form* routine parameterised by a predicate identifying the conjunction or disjunction operator of the chosen fuzzy logic, which keeps the classical and fuzzy code paths unified. Subclasses are bound by an abstract contract covering cloning, negation, equality, name computation, extraction of atomic concepts and roles, and structural substitution, while a handful of static helpers search lists of concepts for a given concept or its negation.

Concept itself carries a ConceptType tag distinguishing atomic concepts from compound structures and manages naming lazily: the string representation caches the result of the abstract name computation on first use, and equality is defined purely by comparing string forms, so structurally identical expressions are interchangeable wherever they appear. Logical composition reads naturally through operator overloading — unary minus and tilde both express negation, while `&`, `|`, and `>>` denote conjunction, disjunction, and implication — although the base class leaves these as stubs for specialised subclasses to implement. Ordering comparisons deliberately strip parentheses before comparing strings lexicographically, keeping sorts stable across expressions that differ only in grouping, and hashing is identity-based rather than string-based, a pragmatic choice that keeps hashing cheap at the cost of the usual hash/equality consistency contract. Nominal detection is handled by a simple substring probe of the string form, and class-level counters together with a special-character naming convention support the generation of fresh, unique concept names whenever the reasoner introduces auxiliary concepts during processing.
