# Summary

A minimization query that computes the smallest value attainable by a given objective expression over a fuzzy description-logic knowledge base.

## Description

`MinQuery` extends the generic `Query` abstraction to pose an optimization problem against a fuzzy ontology: rather than asking a yes/no question, it seeks the minimum degree to which the stored objective expression can hold, subject to all constraints encoded in the knowledge base. The design deliberately separates query construction from execution — the expression is captured at initialization, while the actual work happens at solve time, where the ABox is first materialized on the original knowledge base and the optimization itself is then performed on a clone, ensuring the solving process never mutates the caller's ontology. Execution timing is recorded around these steps to support performance reporting, and a no-op preprocessing hook is retained purely to satisfy the shared query interface. Robustness is handled by catching the inconsistency exception raised during solving and translating it into a dedicated `Solution` value flagged as an inconsistent knowledge base, allowing callers to distinguish a genuine optimization result from a failed premise without dealing with a raw exception. The string representation renders the query in human-readable form as the objective expression followed by a `? >=` placeholder, reflecting that the answer sought is the lower bound of the expression's possible values.
