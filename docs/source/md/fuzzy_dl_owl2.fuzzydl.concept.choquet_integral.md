# Summary

A fuzzy description-logic concept that aggregates a list of weighted sub-concepts through a Choquet integral, allowing the blended result to be negated, conjoined, and disjoined like any other concept in the knowledge base.

## Description

Within a fuzzy ontology reasoner, complex concepts frequently need to be built by blending several simpler ones according to their relative importance, and the Choquet integral is a classic aggregation operator for doing exactly that with fuzzy values. The `ChoquetIntegral` class supplies this capability: it pairs a list of floating-point weights with a corresponding list of `Concept` objects, enforcing at construction time that the two lists have equal lengths and reporting an error otherwise, while gracefully degrading to an empty weight list when no weights are supplied. It derives from the base `Concept` class — registering itself under a dedicated Choquet-integral concept type — and mixes in a shared interface for weighted concept containers, which provides the common machinery for storing and exposing the weights alongside their associated concepts.

Because the aggregation is itself a concept, it must behave like one. Logical composition is achieved by overloading the unary minus, bitwise-and, and bitwise-or operators, each delegating to the corresponding helper on `OperatorConcept`, so integrals can be freely combined with every other kind of concept in boolean-style expressions without any operand being mutated. Traversal of the concept hierarchy is handled by recursive delegation: the set of atomic concepts and the set of roles are obtained by unioning the results reported by each sub-concept, letting the reasoner discover everything reachable beneath the aggregation. Structural manipulation follows a functional style — cloning produces a new instance with shallow-copied weight and concept lists, and replacing one concept with another recursively rebuilds the sub-concept list and returns the negation of the freshly constructed integral, leaving the original object untouched.

Two further details round out the design. The printable name is generated in a fixed parenthesised syntax that interleaves the weights and sub-concepts, serving as the concept's canonical textual identity. Hashing is computed structurally from the weights, the hashes of the sub-concepts, the name, and the concept type, so that two structurally identical integrals hash identically and can safely serve as dictionary keys or set members even though the underlying lists are mutable.
