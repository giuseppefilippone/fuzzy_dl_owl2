# Summary

A class that models triangular fuzzy numbers—uncertain quantities whose membership degree rises linearly from a lower bound to a peak and falls linearly back to an upper bound—providing fuzzy arithmetic, logical combinators, and defuzzification for fuzzy description-logic reasoning.

## Description

TriangularFuzzyNumber specializes TriangularConcreteConcept so that fuzzy numbers can act as concrete concepts inside a fuzzyDL/OWL 2 knowledge base, carrying both a numeric shape and a concept identity. Construction is deliberately flexible: an instance can be built from three numeric parameters, in which case a descriptive name is generated automatically, or from an explicit name followed by the three values, with both paths guarded by assertions on argument count and types. A class-level domain, bounded by the attributes **K1** and **K2**, serves as a global universe of discourse shared by every number; it defaults to the entire real line and can be narrowed through `set_range`, which influences how numbers are named and recognized throughout the reasoning pipeline.

Arithmetic follows the fuzzy extension principle while keeping every operation pure: addition and multiplication combine the lower bound, peak, and upper bound component-wise, whereas subtraction and division pair each operand's lower bound with the other's upper bound so that the result spans the widest support consistent with interval arithmetic, and division additionally rejects divisors that contain zero. All operators return fresh instances rather than mutating their operands, which keeps reasoning side-effect free. Logical negation, conjunction, and disjunction are delegated to OperatorConcept, allowing fuzzy numbers to be embedded directly in compound concept expressions through natural Python operator syntax. For interpretation, the *Best Non-Fuzzy Performance* value defuzzifies a number into a crisp score (the arithmetic mean of its three parameters), and a degenerate triangle whose three parameters coincide is recognized as an ordinary crisp number.

Identity semantics are strict: two numbers are equal only when they share the exact same type and identical parameters, and hashing incorporates the global range alongside the three defining values so that instances behave predictably in sets and dictionaries. Together these choices yield a lightweight, effectively immutable value object that integrates cleanly with the broader concrete-domain machinery of the fuzzy ontology reasoner.
