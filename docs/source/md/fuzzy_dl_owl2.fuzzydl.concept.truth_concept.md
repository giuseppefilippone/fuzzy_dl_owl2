# Summary

Provides the top and bottom truth constants of a fuzzy description-logic concept lattice as lazily cached singletons that behave correctly under conjunction, disjunction, implication, and negation.

## Description

`TruthConcept` is the central class here: it models the universal concept (Top), which is always satisfied and serves as the identity element for conjunction while absorbing under disjunction, and the contradictory concept (Bottom), which behaves in exactly the opposite way. Rather than allowing these logical constants to be instantiated ad hoc, the implementation exposes them through static factory accessors that lazily create and cache a single shared instance per value — a deliberate design decision that prevents large ontologies from allocating huge numbers of identical, immutable objects. The familiar Python operator protocol is overloaded so that `&`, `|`, `>>`, and unary negation perform conjunction, disjunction, implication, and complement respectively, with each operation short-circuiting to the appropriate constant according to the lattice laws (for example, Top conjoined with any concept yields that concept, while anything disjoined with Top collapses to Top). Because these constants are terminal nodes with no internal structure, the concept is treated as atomic throughout the framework: sub-concept replacement is a no-op that simply returns the instance itself, and queries for constituent atoms or associated roles return either the bare instance or empty collections. Equality and hashing are defined structurally from the concept's name and type rather than by object identity, so any two Top instances (or any two Bottom instances) compare equal and remain well-behaved as dictionary keys and set members even when clones are produced. Convenience aliases `TOP` and `BOTTOM` are pre-bound to the singletons at import time, giving the rest of the reasoning engine stable, shared handles on the two extreme truth values.
