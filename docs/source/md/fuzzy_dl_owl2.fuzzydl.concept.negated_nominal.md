# Summary

A fuzzy description-logic concept representing the complement of a single named individual — written `(not { a })` — used to exclude that individual from a domain, typically when expressing range restrictions.

## Description

`NegatedNominal` extends the base `Concept` class and registers itself as an atomic concept, storing the name of the excluded individual and deriving a canonical string representation from it. The excluded individual's name is exposed through a property so that downstream components can recover which individual is being ruled out when processing axioms or restrictions. A key design decision is the reliance on Python's operator overloading: conjunction and disjunction are delegated to the shared `OperatorConcept` helper, keeping the boolean-combination logic in one place rather than duplicating it across concept types. Double negation is deliberately forbidden — applying the unary negation operator raises a `FuzzyOntologyException`, because nested negation of nominals has no meaning in the underlying logic, and failing loudly prevents malformed concepts from silently entering a knowledge base. Instances are hashable based on their individual name, cached display name, and concept type, allowing them to participate in sets and dictionaries alongside other concepts, and a clone operation produces an independent copy for safe structural sharing. One subtle trade-off is that mutating the individual's name stores the new value directly without recomputing the cached display name, which keeps the setter cheap but can leave the two attributes out of sync if the property is reassigned after construction.
