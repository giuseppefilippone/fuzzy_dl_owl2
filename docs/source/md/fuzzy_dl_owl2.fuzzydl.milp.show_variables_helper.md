# Summary

A display-configuration manager for a fuzzy description logic reasoner that records which atomic concepts, individuals, abstract role fillers, and concrete feature fillers should be shown, resolves solver variables to human-readable names, and attaches fuzzy linguistic labels to concrete features.

## Description

ShowVariablesHelper accumulates user preferences about which parts of an ontology's solution should be printed once the underlying mixed-integer linear program has been solved, keeping the reasoning logic cleanly separated from presentation concerns. Visibility is tracked at two granularities — *global* settings that apply to every individual, and *per-individual* settings restricted to named individuals — with a deliberate precedence rule: promoting a role or feature to global scope discards any previously recorded individual-specific entries, and later attempts to register individual-specific entries for an already-global role or feature are silently ignored. Concrete features receive additional treatment because fuzzy ontologies attach linguistic labels to them, so lists of fuzzy concrete concepts are aggregated per feature-individual pair, appending to any existing labels rather than overwriting them, which allows membership degrees to those labels to be displayed alongside the filler value. A separate registry maps internal solver Variable objects to display names so the presentation layer can turn opaque variables into meaningful strings, while read-only membership queries and lenient accessors (returning None or an empty list instead of raising) make the accumulated settings easy and safe to consume. The Java-style method overloading of the original fuzzyDL library is emulated through argument-count dispatch guarded by assertions, and a cloning facility snapshots the entire configuration using fresh containers whose elements are shared by reference, enabling display settings to be preserved or branched when a problem is solved repeatedly under different output preferences.
