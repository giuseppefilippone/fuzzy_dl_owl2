# Summary

A mixed-integer linear programming layer for a fuzzy description-logic reasoner that translates fuzzy concepts, roles, and assertions into decision variables and linear constraints, dispatches the resulting optimization problem to pluggable solver backends such as Gurobi, Python-MIP, and PuLP, and packages the outcome as degrees of satisfaction paired with consistency verdicts.

## Description

The algebraic machinery is layered bottom-up: symbolic variables — each typically standing for a truth degree in the unit interval, with a domain type that automatically determines its numeric bounds — combine with coefficients into immutable terms, terms aggregate into linear expressions carrying a constant offset, and expressions pair with an inequality type to form canonical constraints whose right-hand side is normalised to zero. Operator overloading throughout these primitives lets modelling code read like ordinary mathematical formulas, while deliberate value-object semantics (hashing, equality, and cloning) allow terms, expressions, and constraints to be deduplicated in sets and used safely as dictionary keys.

At the centre sits the *MILPHelper* manager, the optimization core that maps every fuzzy concept or role assertion to a lazily created, cached decision variable under a canonical naming scheme, forces crisp elements to binary domains, and compiles logical axioms, restrictions, and cardinality requirements into linear inequalities. Beyond plain constraints it embeds reusable MILP idioms demanded by fuzzy reasoning — sorting-network encodings for qualified cardinality reasoning, Big-M relaxations for nominal unification, and partition equations enforcing the law of excluded middle. Solving is deliberately backend-agnostic: a single dispatch method delegates to Gurobi, Python-MIP with CBC, or PuLP with CBC, GLPK, HiGHS, or CPLEX, importing each library lazily so only the chosen backend needs to be installed, emulating semi-continuous variables where a backend lacks native support, and optionally exploiting weakly coupled problems by splitting a variable co-occurrence graph into connected components that are each solved as an independent, much smaller sub-problem.

Outcomes are captured in a dual-mode solution object that records either a numeric degree of satisfaction (implying consistency) or an explicit consistency verdict, and that accumulates the bindings of variables the user asked to expose. A separate display-configuration manager records which concepts, individuals, and feature fillers should be shown and attaches fuzzy linguistic labels to concrete features, keeping presentation concerns cleanly separated from the reasoning logic. A deep-copy cloning facility rounds out the design, letting the reasoner explore alternative scenarios without mutating the shared problem state.

## Modules

- [`fuzzy_dl_owl2.fuzzydl.milp.expression`] — A linear-expression class that models the algebraic form *c₀ + Σᵢ cᵢxᵢ* and serves as the primitive building block from which all constraints and objective components are composed in the mixed-integer linear programming layer of a fuzzy description-logic reasoner.
- [`fuzzy_dl_owl2.fuzzydl.milp.inequation`] — A linear constraint abstraction that encodes inequalities of the form *E* ⋈ 0 (with the operator being =, ≤, or ≥) for use in mixed-integer linear programming within a fuzzy description-logic reasoning system.
- [`fuzzy_dl_owl2.fuzzydl.milp.milp_helper`] — A Mixed-Integer Linear Programming (MILP) manager for a fuzzy description-logic reasoner that translates fuzzy concepts, roles, and assertions into decision variables and linear constraints, then dispatches the resulting optimization problem to pluggable solver backends such as Gurobi, Python-MIP, and PuLP.
- [`fuzzy_dl_owl2.fuzzydl.milp.show_variables_helper`] — A display-configuration manager for a fuzzy description logic reasoner that records which atomic concepts, individuals, abstract role fillers, and concrete feature fillers should be shown, resolves solver variables to human-readable names, and attaches fuzzy linguistic labels to concrete features.
- [`fuzzy_dl_owl2.fuzzydl.milp.solution`] — A value object that captures the outcome of a query over a fuzzy knowledge base, pairing a numerical degree of satisfaction with the knowledge base's consistency status and any variable bindings produced during solving.
- [`fuzzy_dl_owl2.fuzzydl.milp.term`] — An immutable algebraic term that pairs a numeric coefficient with a variable, providing the atomic building block for the linear expressions used to encode fuzzy description logic reasoning as mixed-integer linear programming problems.
- [`fuzzy_dl_owl2.fuzzydl.milp.variable`] — A symbolic variable abstraction for mixed-integer linear programming in which each named variable represents a degree of satisfaction in fuzzy description logic reasoning, carrying a domain type (binary, integer, continuous, or semi-continuous) that automatically determines its numeric bounds.
