# Summary

A converter that transforms FuzzyDL fuzzy description-logic knowledge bases into standard OWL 2 ontologies, preserving the fuzzy semantics by embedding them as structured annotations.

## Description

The conversion logic is centred on the **FuzzydlToOwl2** class, which parses a FuzzyDL source file into an in-memory knowledge base and then systematically maps its concepts, roles, individuals, and axioms onto OWL 2 classes, object and data properties, named individuals, and axioms. Because OWL 2 has no native notion of degrees of truth, a deliberate design decision keeps the output fully standard-compliant while retaining the fuzzy information: truth degrees, linguistic modifiers, and aggregation operators are serialised as small XML fragments and attached to the relevant entities and axioms through a dedicated annotation property. Complex fuzzy constructs—modified concepts, weighted concepts, and aggregators such as weighted min/max/sum, OWA, and Choquet, Sugeno, and quasi-Sugeno integrals—are *nominalised*, meaning each is represented by a freshly generated atomic class whose annotation records the original fuzzy definition, whereas concrete fuzzy concepts (crisp, left-shoulder, right-shoulder, triangular, trapezoidal) become OWL datatypes restricted to a numeric interval and annotated with their membership-function parameters. Any axiom whose degree differs from 1 receives an additional degree annotation, so crisp axioms remain untouched while fuzzy ones stay reconstructible by downstream tools.

The `run` method orchestrates the whole pipeline: it first annotates the ontology with the underlying fuzzy logic, then declares atomic concepts, concrete concepts, modifiers, assertions, and individuals, translates equivalences, subsumptions, and disjointness axioms, and finally encodes property characteristics such as domains, ranges, reflexivity, symmetry, transitivity, inverse relations, sub-property hierarchies, and functionality before saving the result to disk. Identifiers are generated under a configurable base IRI with separate sub-namespaces per entity kind (classes, data and object properties, individuals, datatypes, annotation properties), which keeps the produced ontology readable and well organised, and a small command-line entry point wires the converter to input and output paths supplied as arguments.
