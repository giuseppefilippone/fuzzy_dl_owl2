# Summary

A fuzzy description-logic assertion stating that an individual belongs to a concept with at least a given membership degree, rendered in the conventional form *individual:concept >= degree*.

## Description

Assertion serves as the fundamental knowledge primitive in a fuzzy ontology reasoner, capturing graded membership rather than the crisp true/false statements of classical DL. Each assertion couples three components — an individual, a concept, and a degree that acts as a lower-bound threshold — and the assertion is considered satisfied whenever the individual's actual membership in the concept meets or exceeds that threshold. The components are stored plainly and remain fully mutable through getters and setters, a deliberate choice that lets reasoning components rewrite or refine assertions in place; a copy operation produces only a shallow replica, so duplicated assertions continue to share their underlying individual, concept, and degree objects. Supporting helpers expose the concept's internal type, which allows downstream logic to dispatch on whether an assertion involves an atomic or otherwise structured concept, and a degree-free name of the form *individual:concept* identifies the assertion independently of its threshold.

The most deliberate — and most unusual — design decision lies in the equality semantics. Two assertions compare as equal either when their full string representations coincide, or when they name the same individual and concept and the first assertion's numeric degree is strictly *smaller* than the second's. This asymmetric, order-sensitive rule effectively treats a stronger assertion (higher threshold) as subsuming a weaker one, which is useful when a reasoner absorbs new knowledge or checks whether an incoming assertion is already entailed by a stricter one already on record; the trade-off is that equality is no longer symmetric, so *a == b* does not imply *b == a*. String conversion follows the standard fuzzy-DL notation *name >= degree*, and the debug representation simply delegates to that informal form, keeping logs and interactive sessions readable while the individual type is imported only under `TYPE_CHECKING` to sidestep circular dependencies.
