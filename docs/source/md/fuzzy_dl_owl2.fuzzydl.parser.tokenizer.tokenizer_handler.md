# Summary

A pluggable tokenization layer for the fuzzy-DL parser that wraps interchangeable scanning backends — an always-available pure-Python regex tokenizer plus optional compiled re2c/flex string and file scanners — behind a registry that automatically selects the fastest usable one.

## Description

The design revolves around a single normalised output contract: every backend, whether implemented in pure Python or compiled C, emits the same `(kind, value, lower/raw, offset)` 4-tuples terminated by an `T_EOF` sentinel, which frees the recursive-descent parser from knowing or caring which scanner actually ran. The central `TokenizerHandler` registry instantiates the candidate backends in preference order at construction time and adopts the first one that reports itself available, giving graceful degradation: when the compiled Cython or CFFI extensions are built they are used for speed, and when they are absent the pure-Python regex tokenizer — which can never fail to import — silently takes over. The compiled backends probe their entry points defensively inside their constructors, so a missing or unbuilt extension simply leaves the corresponding callable unset and marks the backend unavailable rather than raising at import time.

Lexically, the scanners skip whitespace, commas, and `#`/`%` line comments; classify parentheses, braces, and brackets; treat quoted strings as identifier-like tokens; and convert numeric literals into `int` or `float` values. Identifiers that embed the `*` and `+` characters are split into separate operator and operand tokens unless they match a protected fuzzy-DL keyword, which keeps compound expressions scannable without breaking reserved words. The compiled scanners return raw integer code arrays that are remapped onto the parser's token kinds, with keyword codes folded into identifier tokens carrying their lowercase spelling so downstream matching stays case-insensitive.

For large inputs the file-oriented backend streams rather than materialising everything at once: once a source exceeds a roughly one-megabyte threshold, it is partitioned into batches that end on whole top-level parenthesised forms — the depth counting correctly ignores strings and comments — so peak memory stays bounded and the parser never receives a partially scanned form. A module-level handler singleton and a convenience tokenize function expose the selected backend to the rest of the parser package, while the file entry point falls back to reading the entire file and delegating to the best in-memory backend whenever no compiled file scanner exists.
