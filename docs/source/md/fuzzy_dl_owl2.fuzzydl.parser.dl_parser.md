# Summary

A pyparsing-based parser for the fuzzy Description Logic language that reads textual knowledge base files and constructs a fully populated **KnowledgeBase** together with the list of queries to be answered against it.

## Description

The central `DLParser` class assembles the complete grammar of a fuzzy DL language and attaches static parse-action callbacks to each rule, so that recognising a statement immediately transforms the matched tokens into domain objects and mutates a shared, class-level knowledge base. Parsing is therefore side-effect driven: concept and modifier definitions, fuzzy concrete concepts of various shapes, triangular fuzzy numbers with arithmetic, concrete features, datatype restrictions, axioms, MILP expressions and constraints, and debugging "show" directives are all registered on the knowledge base as they are encountered, while query statements accumulate in a companion class-level list. The primary entry point, `get_kb`, resets this state, loads configuration from a CONFIG.ini file, parses the input either line by line (in verbose debug mode) or as a whole file, and returns the knowledge base and its queries; the `main` method then goes further, solving the knowledge base and answering each query in turn while logging solutions, timings, and the underlying logic language, and falling back to a default answer when the ontology turns out to be inconsistent.

The grammar deliberately supports multiple fuzzy semantics — Łukasiewicz, Zadeh/Gödel, and classical — and the parse actions enforce logic-specific constraints at read time, for example rejecting Gödel or Łukasiewicz operators under the classical reasoner and selecting the appropriate conjunction, disjunction, or implication implementation based on the currently configured logic. Semantic validation is pervasive: weights in weighted aggregations and in OWA, Choquet, Sugeno, and quasi-Sugeno integrals are checked for non-negativity and correct normalisation, concepts used in abstract positions are verified not to be concrete, roles are prevented from being simultaneously concrete and abstract, and any referenced modifier, individual, feature, or fuzzy concept must be defined before use. Errors are surfaced through a central error-reporting utility, and unexpected failures during parsing are wrapped in a `FuzzyOntologyException` with the original cause chained, mirroring the behaviour of the original Java fuzzyDL reasoner whose syntax is reproduced here.

Several engineering decisions address robustness and diagnosability. Left recursion is enabled in pyparsing so that deeply recursive concept expressions parse correctly, and the parse entry points temporarily lift Python's recursion limit to cope with heavily nested input. Query statements are deliberately matched before plain concept expressions in the top-level grammar so that short query forms are not misinterpreted as modifier applications. When debug output is enabled, every parse action can be traced and a timestamped diagnostic log is written into a dated directory tree, and the class as a whole is instrumented so that method invocations can be observed during troubleshooting.
