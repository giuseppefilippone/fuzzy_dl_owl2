# Summary

A tokenizer for the fuzzy description-logic (FDL) input language that drives a compiled C scanner through CFFI and returns flat, NumPy-backed token streams built from either memory-mapped files or in-memory byte strings.

## Description

The vocabulary of the FDL language is defined here as a table (`TOK_NAMES`) mapping integer token codes to display names, covering punctuation, arithmetic and comparison operators, numbers, bare identifiers, and the language's extensive keyword set — fuzzy logic families such as *lukasiewicz* and *zadeh*, concept and role declarations, quantifiers, weighted aggregation operators like OWA, Choquet and Sugeno, and the various satisfiability and instance queries. Because the table is generated alongside the native scanner, the integer codes stay in sync with what the C lexer actually emits. Scanning itself is delegated to a native lexer loaded through CFFI, with a primary and a fallback import path attempted and an `AVAILABLE_LEXER` flag signalling whether the backend is present so callers can degrade gracefully.

Tokenization runs in two passes over a NUL-terminated buffer: a first C call merely counts tokens so that three parallel int32 arrays — type codes, byte start offsets, and byte lengths — can be allocated to the exact size, and a second call fills them. This structure-of-arrays layout keeps the hot path free of per-token Python objects; the resulting `Tokens` stream retains ownership of the source buffer so span offsets remain valid, decodes a token's text lazily and only when requested, and answers keyword or identifier queries with pure integer comparisons. Context-manager support guarantees orderly teardown, releasing the exported memoryview and dropping the CFFI pointer before the underlying mapping is unmapped.

Two buffer abstractions feed the same two-pass routine. Files are opened read-only and memory-mapped, exploiting the fact that mmap zero-fills the final partial page to obtain the NUL sentinel the re2c backend requires essentially for free; empty files and files whose size is an exact page multiple — the one case mmap cannot zero-pad — receive small special-case treatments. An in-memory counterpart wraps already-resident bytes with an appended NUL and mirrors the same interface, letting the public entry points (`get_tokens` for whole files, `get_tokens_from_bytes` for parser chunks) share all of their logic, while the mmap-based path never builds a whole-file Python string, keeping memory usage low for large ontologies.
